## Структура

```
smustard_PathCopy.rb          # loader, SketchupExtension, 439 байт
smustard_PathCopy/
  pathcopy.rb                 # весь код, 461 строка, один класс-инструмент
  pathcopyCursor.png          # курсор (2005 г.)
  PathCopy{Large,Small}.png   # иконки тулбара 24/16 px
  PathCopy{Node,Spacing}*.png # мёртвые ассеты, не используются с 2.200
```

Ровно один класс `Smustard::PathCopy` — он же Tool, он же UI, он же геометрия.

## Как работает

1. Инструмент активируется, читает `model.selection.first`; если это `Edge` —
   берёт его `.curve` (или сам edge) как путь.
2. Клик по группе/компоненту → считаются точки вдоль пути.
3. Два режима, переключаются вводом в VCB: любое число = шаг, **ноль = по вершинам**.
4. Копии ставятся с поворотом только вокруг Z по «плоскому» азимуту сегмента.

## Дефекты

### Функциональные (главные)

| # | Проблема |
|---|---|
| F1 | **Путь = один `Edge` или один `Curve`.** Цепочка несваренных рёбер не поддерживается — отсюда знаменитое «сначала сделай Weld». Контур грани, набор выделенных рёбер, несколько путей — не работают. |
| F2 | **Компонент теряет свою трансформацию.** `ents.add_instance(item.definition, Geom::Transformation.new(points[i]))` — чистый перенос. Масштаб, поворот, зеркало исходного инстанса выбрасываются. |
| F3 | **Группы и компоненты ведут себя по-разному.** Для группы (`item.copy` + `gp.transformation = item.transformation`) собственная трансформация сохраняется, для компонента — нет. |
| F4 | **Поворот только вокруг Z** (`flat_angle`). 3D-путь с уклоном игнорируется; на строго вертикальном сегменте вектор вырождается в нуль и функция возвращает произвольные 180°. |
| F5 | **Замкнутая кривая** (окружность) даёт дубль копий на стыке — первая точка ставится безусловно. |
| F6 | Нет: количества копий (делителя — он висит в ToDo с 2005 г.), отступов от начала/конца, выравнивания «по центру», подгонки шага под длину, смещения от пути, случайного разброса, масштабирования по длине. |
| F7 | Нельзя копировать несколько выделенных объектов сразу. |
| F8 | Копии не группируются, не получают тег/слой, не именуются. |

### Ошибки и падения

| # | Проблема |
|---|---|
| B1 | `pfirstedge = path.edges[1]` → `nil.start` **падает**, если у кривой ровно одно ребро. |
| B2 | Отрицательный шаг проходит валидацию (`value == 0` ловит только ноль) → `vec.length = -N` → `ArgumentError`. |
| B3 | Шаг ровно на границе даёт `runningLength == 0` → `vec.length = 0` → `ArgumentError` «zero length vector». |
| B4 | **Нет лимита на число копий.** Шаг 0.001" на длинном пути = миллионы итераций `while runningLength < 0` → SketchUp намертво виснет. |
| B5 | `get_path` может оставить `@path == nil`, дальше `@path.edges` → `NoMethodError`. Клик по грани молча ничего не делает, без обратной связи. |
| B6 | `deactivate` проверяет `@drawn`, которая нигде не присваивается. |

### Undo и производительность

| # | Проблема |
|---|---|
| U1 | `Sketchup.undo` внутри `onUserText` — дёргается **общий Undo приложения**, а не своя операция. При устаревшем `@madecopies` откатывает чужую работу пользователя. Отсюда «кривизна» при переборе шага. |
| U2 | `model.start_operation("pathCopyComponent")` без `disable_ui=true` → перерисовка на каждой копии, сотни копий ставятся секундами. |
| U3 | Операции не прозрачные/не сцепленные — в истории Undo мусор из десятка `pathCopyComponent`. |

### UX

| # | Проблема |
|---|---|
| X1 | **Нет превью.** Ни `draw`, ни `onMouseMove` — результат виден только после клика. |
| X2 | Режим «по вершинам» включается вводом `0` в VCB. Не документировано в интерфейсе, не угадывается. |
| X3 | Нет диалога настроек, нет модификаторов (Ctrl/Shift/Alt), нет `getInstructorContentDirectory`. |
| X4 | `puts "activating..."` и ещё десяток отладочных `puts` спамят Ruby Console при каждом действии. |
| X5 | Настройки не переживают перезапуск — нет `Sketchup.read_default` / `write_default`. |

### Инфраструктура / совместимость

| # | Проблема |
|---|---|
| I1 | Манифест грузит `smustard_PathCopy/PathCopy.rb`, а файл на диске — `pathcopy.rb`. На регистрозависимой ФС (macOS case-sensitive, Linux) расширение не загружается. |
| I2 | `Sketchup.find_support_file("pathcopyCursor.png", "Plugins/smustard_PathCopy")` — жёстко зашитый путь вместо `__dir__`. Ломается при нестандартном каталоге плагинов. |
| I3 | Меню вешается в `UI.menu("Plugins")`; современное имя — `"Extensions"`. |
| I4 | Глобалы `$submenu`, `$smustard_toolbar` — засорение глобального namespace. |
| I5 | Тулбар не вызывает `.restore` — положение не запоминается. |
| I6 | Иконки только PNG 16/24 px. Нет SVG (Win) / PDF (Mac) → мыло на HiDPI. |
| I7 | Нет `extension_id`, `homepage`. Сборка из Wayback не подписана — при политике загрузки «Identified Extensions Only» SketchUp её не примет. |
| I8 | Ruby 1.8-стилистика: `0.upto(n-1)`, `collect!`, без `frozen_string_literal`, без namespace-версионирования. Под Ruby 3.2 (SU 2024+) работает, но выдаёт предупреждения в verbose. |
| I9 | Нет локализации, нет тестов, нет CI-сборки .rbz. |

## Вывод

Код рабочий, но это скрипт 2005 года с одной заплаткой 2014-го: один класс на
461 строку, состояние в переменных класса, отладочный вывод, ручной обход рёбер
без нормализации пути и Undo через `Sketchup.undo`. Модернизировать правкой
нельзя — надо переписывать ядро (нормализация пути → сэмплирование по длине дуги
→ построение трансформаций), а лицензия Smustard всё равно запрещает деривативы.
